# Stage 25 — Portfolio (Ongoing)

## What this stage actually is

Unlike every other stage, this isn't new material — it's curating and
polishing **25-30 substantial projects** drawn from Stages 0-24 into a
real, hireable portfolio. No new `SPEC.md` files are generated per
"project" here, because the projects already exist; this is about
presentation and selection, which can't be decided meaningfully until
the actual body of work exists.

## Target spread (per ROADMAP.md)

A balanced selection across:

- **Core Systems (C):** hex editor, text editor, shell, memory
  allocator, HTTP server, thread pool, JSON parser, ELF parser, PE
  parser, packet sniffer
- **Windows:** Win32 process launcher, custom DLL loader, process/
  module enumerator
- **Security:** port scanner, HTTP proxy, binary patcher, crackme
  write-ups, custom fuzzer, malware triage tool, YARA rule pack, Sigma
  rule pack
- **Hardware:** CHIP-8 emulator, bootloader, embedded firmware, CPU
  simulator
- **AI:** malware classifier, AI log analyzer, AI reverse-engineering
  assistant, AI threat-hunting assistant

Notice this is mostly a **subset of projects you've already built** in
Stages 1-24, not new work — the "project" here is choosing which ones
represent you best and making them presentable.

## What "portfolio-ready" actually means (not hand-holding — a real bar)

For each project you select:

1. **A real README** — what it does, why you built it, how to run it,
   and (for the security-relevant ones) what you learned about the
   underlying vulnerability/technique class. Not a one-line description.
2. **Evidence intact** — the same acceptance-criteria evidence
   (`valgrind` output, test results, etc.) you produced during the
   original project should still be visible in the repo or its history,
   not scrubbed away for looking "cleaner."
3. **Honest scope** — don't inflate a Stage 1 exercise into something it
   isn't. A hiring manager who's done this work themselves will notice,
   and honesty about scope is itself a positive signal.
4. **It actually still runs** — pick projects you're willing to have
   someone clone and build right now, not ones that quietly broke
   somewhere along the way.

## When you actually reach this stage

Come back for a real working session on:
- Which specific projects (of everything built by then) to include
- Whether any need meaningful rework before being portfolio-worthy
  (this is a legitimate reason to revisit old code, unlike bulk-
  generating ahead of time)
- README quality pass across the selected set
- Whether a portfolio "index" page/repo tying everything together is
  worth building (a reasonable capstone-style project in its own right)

This session should happen with the real, finished body of work in
front of us — not speculated now.
